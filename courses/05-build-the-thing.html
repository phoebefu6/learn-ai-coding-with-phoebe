Part 1 · covers the tool landscape

The four tools, and the catch each one does not advertise

8 min live

Every comparison post you have read is out of date, because three of these four changed something structural in 2026. Here is the shape of each one, and then the part you only find out on day three.

★ What you walk out with tonight. Your feature actually built, a plan-first workflow you have run once so you know what it feels like, and a cost number that means something: what a merged change costs you, not what a prompt costs you.

Check the signup status before you plan a cohort. As of the June 2026 changelog, Copilot signups are paused for Student, Pro, Pro+ and Max, and for Business on Free and Team organisations since 2026-04-22. Nothing derails a training session faster than eight people who cannot create an account.

Self-studyWhy the Codex naming matters more than it sounds3 min▶

The 2021 Codex completion models were deprecated on 2023-03-23. Even codex-mini-latest was removed on 2026-02-12. So when someone tells you Codex was shut down, they are quoting a true fact about a dead thing while you are asking about a live product line.

This is a small example of a habit worth generalising: in this field the name and the thing drift apart faster than the documentation gets rewritten. "Composer" in Cursor is a mode and a model. "Copilot" is an IDE completion, an agent mode, a cloud agent and a code reviewer. Before you accept advice, work out which noun the author had in front of them.

The practical upside of Codex today: it is the only one of the four that publishes hard numeric rate limits. If you need to write a capacity plan somebody will hold you to, that is not a small thing.

Self-studyLet the constraint choose, not the review3 min▶

Tool arguments go on forever because people compare capability, and at this level the capabilities have converged. Constraints have not. Four questions settle it faster than any comparison table.

  • What are your developers on? Claude Code's bash sandbox is macOS Seatbelt or Linux isolation, and native Windows is unsupported. If half the team is on Windows without WSL, that is the end of the conversation.
  • Do you have to forecast the spend? Codex publishes hard numeric rate limits. Claude Code publishes only the structure plus a real cost benchmark. Cursor's two token pools and Copilot's credits both need modelling.
  • Where does the review already happen? If your team lives in pull requests, Copilot's cloud agent lands in a workflow you already have, with the human merge requirement enforced for you.
  • Are you teaching a group next month? Then check account availability first. Paused signups have ended more workshops than any missing feature.

None of this is loyalty. Most people who use these seriously end up with two, and the second one exists because of a constraint rather than a preference.

Part 2 · covers agent modes

How much rope, and where the gate goes

5 min live

Every one of these tools now offers a spectrum from "suggest a line" to "go away and open a pull request". The decision is not which end is better. It is which rung you are on for this particular task, and whether you know what you signed up to review.

LiveWhy plan-first is the rung that pays for itself3 min▶

Cursor puts Plan Mode on Shift+Tab. Claude Code has a plan-shaped permission mode among its six. Codex and Copilot both let you ask for an approach before an edit. Different words, same move: make the model state its intent while it is still cheap to disagree.

Three things a plan gets you that a diff cannot.

  • You see the files it intends to touch before it touches them. Half of all bad agent runs are visible right there, in a file list that includes something you did not expect.
  • You argue at the level of approach. Correcting "use the existing repository layer, do not add a second one" costs one sentence in a plan and an afternoon in a merged branch.
  • Your review has a shape. Reading a 400-line diff cold is genuinely hard. Reading it against a plan you already agreed to is a comparison, and humans are much better at comparisons than at cold reads.

This is session 1's finding wearing different clothes. Writing the spec before the prompt took the playground from zero of five to five of five. A plan is a spec you did not have to write yourself, that you get to correct before anything is built.

LiveWhat "the agent opens a PR" changes about your job2 min▶

Rung 4 is the one people underestimate, because it feels like delegation and it is actually a change of role. GitHub states the boundary plainly: "Draft pull requests created by Copilot cloud agent must be reviewed and merged by a human." Copilot's cloud agent sessions also cap at 59 minutes, which is a useful forcing function: if the task cannot be described tightly enough to finish inside an hour, it was too big to hand over.

So your work moves. You spend less time typing and more time doing the three things that were always the expensive part:

  • Scoping the task well enough to be handed over, which is most of the value and where most of the failures start.
  • Reviewing an unfamiliar diff, written by something that does not share your conventions unless you told it to.
  • Owning the merge. Session 4's rule holds all the way up: no autonomy mode moves the responsibility. It only moves the moment you exercise it.

And remember the injection lesson while you are up here. A cloud agent reading an issue written by an external contributor is reading text from a stranger. That is exactly the surface CamoLeak used.

Part 3 · covers cost

You are measuring the wrong unit

4 min live

Almost every cost discussion in this field is about the price of a prompt, a request, a credit or a token. None of those are the thing your employer is buying. They are buying merged changes.

LiveThe numbers that exist, and the one you have to make yourself4 min▶

Two published anchors are worth knowing.

  • Claude Code's own docs give a real benchmark: "around $13 per developer per active day and $150-250 per developer per month". That is unusually candid for a vendor and it is the number to quote when someone asks what this costs.
  • Copilot moved to GitHub AI Credits on 2026-06-01, where 1 credit equals $0.01. That conversion is the useful part, because it turns an internal currency back into money you can put in a spreadsheet.

Cursor's move to two token pools and Codex's bundling into ChatGPT plans mean neither gives you a clean per-developer figure either. So build your own, and build it in the unit that matters:

★ The metric worth tracking cost per merged change = (tool spend over the period) / (changes that actually merged in the period) Not cost per prompt. Not cost per accepted suggestion. A prompt you threw away cost you money and produced nothing.

Track it for a month and two things usually happen. The number is lower than the anxiety about it, and the variance between people is enormous. That variance is the interesting finding, because it is a workflow difference and workflow is learnable.

Watch the denominator

Recall session 1: developers forecast a 24 percent speedup, believed afterwards they had been 20 percent faster, and were measured 19 percent slower on their own repositories. Your sense of the numerator is unreliable and your sense of the denominator is worse. Count merges from the log, not from memory.

Build-along

Build the feature, plan-first, posture on

★ 22 min · everyone builds

Whichever tool you have. The workflow is the same everywhere and it is the point of the exercise, not the vendor. Start by saying your permission posture out loud, the one you wrote in session 4.

"Add rate limiting to the API."

Nine minutes later: a new middleware, a new dependency you have not heard of, an in-memory counter that resets on deploy, and edits in four files including one you did not know existed.

Your review starts cold, at 400 lines, with no idea what it was trying to do.

"Plan first. Rate limiting on the write endpoints only, using the Redis client already in this repo. No new dependencies. Show me the files you would touch."

Plan comes back in forty seconds. You delete one step, name the config file, then approve.

Your review is a comparison against a plan you agreed to, not a cold read.

1 · State the posture, then set it. Say the sentence from session 4 out loud, then actually configure it. Not the bypass mode, unless you are in a container with no internet, which is the only place the vendor says it belongs.

2 · Ask for a plan, not a change. Name the constraint, the files that are off limits, and the libraries already in the repo. The plan should come back in under a minute. If it comes back vague, the ask was vague.

3 · Argue with the plan. Delete a step. Rename a file. Reject a new dependency. This is the cheapest minute of the whole session and most people skip it because a plan looks like an answer.

4 · Let it build, and read the approval prompts properly. Use the mock below as your checklist. Every prompt you click through without reading is a decision you made anyway, just faster.

5 · Run the session 4 supply-chain check on anything new. If the agent added an import, it goes through the four steps before you keep it. This takes about a minute and it is the last honest moment to catch it.

6 · Note two numbers. Wall-clock time from ask to working code, and how long the review took. Those two go in your cost-per-merged-change tally. One data point is not a study, but six sessions of them is yours.

If you only take one habit from tonight. Ask for the plan. It costs forty seconds, it makes the review a comparison instead of a cold read, and it is the one move that works identically across all four tools regardless of what they rename next quarter.

Homework

Before session 6

30 min
  1. Finish the feature. It should be working and reviewed by session 6, because session 6 is about getting it merged without hurting anybody.
  2. Run one task at rung 4. Something small and genuinely boring, handed to a cloud agent or an unattended run, and reviewed like an external contribution. You need one experience of this, not an opinion about it.
  3. Start the cost tally. Tool spend for the month divided by changes that actually merged. Two numbers in a note. Compare it to the published $150-250 per developer per month anchor.
  4. Check your plan-to-diff ratio, once. On your next three tasks, ask for a plan on two of them. Note which reviews felt harder. That is your own evidence, and you will trust it more than mine.
  5. Look up the current shape of your own tool. Not a blog post, the vendor's docs page, dated. Three of these four changed something structural this year and yours will change again.
Check yourself

Three questions

Clear all three and session 5 gets stamped in your passport.

1 · Someone tells you "Codex was deprecated years ago". What is the accurate response?

The name has meant three different things. The originals went on 2023-03-23 and codex-mini-latest was removed on 2026-02-12. What exists today is a CLI, an IDE extension and a cloud agent, and it is the only one of the four publishing hard numeric rate limits.

2 · What does Claude Code publish about its rate limits?

The structure is documented, the numbers are not. Any "X hours per week" figure you have seen is folklore. The docs do publish a real cost benchmark though: around $13 per developer per active day and $150-250 per month.

3 · Why is asking for a plan before an edit worth the forty seconds?

You also see the file list before anything is touched, and you can reject an approach for the price of one sentence. It does not remove the review; GitHub still requires a human to review and merge cloud agent pull requests, and so should you.
